# 引擎公开面：模组可以依赖哪些符号

模组是编好的机器码，它引用的宿主符号在**加载时**才解析。所以"哪些符号算公开的"不是文档礼貌，而是
一条要执行的规则：清单外的引用，构建时**编译失败**、加载时**拒绝并指名**（`engine.api` 是机器读的那份）。

## 一、这份清单是怎么来的（实测，不是估的）

`codetab dump mine.codetab` 给出本体自己的表**没有被表内解答**的符号，也就是它真正向宿主索取的。
Release 表（772 节 / 2485 符号，由 `codetab build` 编）一共 **159** 个，去重后：

| 来源 | 个数 | 是什么 |
|---|---|---|
| `t2d::` | 57 | 框架服务：日志、.ecfg、随机数、相机、字体与文字、精灵批、动态库、路径 |
| `ore::` | 25 | 渲染与平台：Renderer、rhi、Window、Image、Application、InputServer |
| `mine::` | **0** | **游戏自己全在表里**，合并时内部解答——这就是"整块本体进表"的样子 |
| libc / libstdc++ | 77 | 平台层，**不属于**我们的 API，模组随意用（表不再带异常机制，原来那 92 个里有 15 个是 `__cxa_*`/`_Unwind_*`） |

引擎的那 82 个（`t2d::` + `ore::`）就是公开面的**下限**：本体要用的，模组至少要能用。实测它们**全部**
在 `engine.api` 里（启动器报告 0 个越界）。一个模组通常只用其中一小部分——多数只碰日志、.ecfg、注册表
与世界查询。

## 二、分层

| 层 | 模块 | 个数 | 政策 |
|---|---|---|---|
| **A 常用 + 稳定** | `t2d/core` 28、`t2d/text` 10 | **38** | **冻结**：改动 = 显式决定 + 引擎版本号 +1 |
| **B 常用但会变** | `t2d/render` 14、`ore/app` 9、`ore/platform` 6、`ore/rhi` 5、`t2d/net` 5、`ore/renderer` 4、`ore/debug` 1 | **44** | **提供，但会随渲染器/网络/加载机制改**；加载时照常校验 |
| **C 不提供** | `mine/app.h`（应用外壳）、`mine/sandbox.h`（开发工具）、各 `.cpp` 内部、模组宿主内部 | — | **拒绝**并指名符号；要改行为就覆盖本体表里的符号 |
| **平台层** | libc、libstdc++、Vulkan、GLFW | — | 不是我们的 API；校验时**不要求**在清单里 |

分层依据是**改动频率**（本仓库的提交数，实测）：`ore/app/application.h` 5 次、`t2d/sim/tilemap.h` 4 次、
`t2d/render/sprite_batch.h` 与 `ore/platform/window.h` 各 3 次，而 `t2d/core`、`t2d/text` 的头文件基本
1–2 次。改得多的进 B（提供，但别指望不动），改得少又常用的进 A（冻结）。

`t2d/sim` 现在**不在清单里**：游戏自己用的是 `mine::ContentGrid`，本体这张表不需要它。需要它的模组会在
构建期被拒绝并指名——比"用了但没人管"清楚。

## 三、怎么执行（已经落地）

1. **构建期**：`codetab build|pack --api engine.api`——表里引用到的引擎符号逐个对照清单，越界即**构建失败**，
   在作者还能改的时候报出来。本体自己的表就是这么打的（`games/mine/CMakeLists.txt`），演示模组也是。
2. **加载期兜底**：启动器读随可执行文件走的 `engine.api`，对每个模块**真正向宿主索取**的符号查表；
   不在清单 → **拒绝该模块**并逐个指名。`requires` 的版本校验照旧：版本是粗筛，符号是细筛。
3. **随时可查**：`codetab api --surface engine.api <表>` 对任何已经存在的表给出同样的结论；
   `--host 1.1` 可以问"引擎往前走一个版本会怎样"。
4. **规则本身**：清单内跨整个 major 放行、一声不响；清单外同版本静默、相差一个 minor 警告后仍然加载、
   再远拒绝；major 不同一律拒绝（`t2d::api_verdict`，见 `TABLES.md` §5.5）。

## 四、还没定的（等实现时再收）

* **生成器**：清单目前由上面的实测产出（`engine.api` 头部写明来源），"按头文件声明自动生成"还没写。
  在那之前，改动靠人改 `engine.api`，改了什么在 diff 里看得见。
* `--allow-internal`（开发期自查用）没做：C 层现在就是拒绝，没有旁路。
* 模组**覆盖本体函数**（`mine::`）不进清单：任何强符号都能覆盖，靠合并报告兜底——覆盖是要的能力，
  报告已经看得见。
* 版本号怎么发：A 层一改就必须动 `engine.api` 第一行；B 层改动可以不动（B 层本来就允许变）。
* **这份清单只有名字**：mangled 名里没有返回类型（实测 `int f()` 与 `double f()` 都是 `_Z1fv`），
  更没有结构体布局、vtable 形状与编译开关。所以"符号还在清单里"只说明符号还在。
  类型与形状那一层由**构建记录**管：每个表带 `abi=`（工具链问编译器得到），启动器自己那份是随可执行文件走的
  `engine.abi`，加载时指纹相同才合并、不同即拒绝并指名。见 [`ABI.md`](ABI.md) 与 [`TABLES.md`](TABLES.md) §5.6。
