# 模板包

一个内容包的骨架：**一个目录**——`pack.ecfg`（这个包是谁）、若干内容文件、一份说明、一个 `art/`。

    cp -r packs/template packs/my_pack
    # 改 pack.ecfg 里的 id，去掉 content.ecfg 里条目的注释，开始写
    # 想分文件就再建几个 .ecfg：一种类别一个（items.ecfg / structures.ecfg），或者一个功能一个

## 写的时候记住三件事

1. **名字是接口**：存档只存数字 id，名字到 id 的映射随存档走。改名字等于换了一个东西；
   在文件中间插入一条，会让它后面同类内容的 id 全部 +1——引擎按名字重新定位已放置的格子，
   所以这不会毁掉你的地图，但 id 会变。
2. **同名内容报冲突，不合并**：本体内容先注册，你的包只能在它后面追加；重名会被报告并保留先注册的那个。
3. **字段是你的**：引擎只读"名字"，不读字段——**例外是 `image` 与 `random_reverse`**（见下）。
   字段可以随便改形状，不影响存档。

**包的身份来自目录名或 `pack.ecfg`**：没有 `pack.ecfg` 时，目录名就是 id；有它时以里面的 `id` 为准。

## 贴图：多边形**风格**的图片

已确认的美术方向是"多边形风格"，**但仍然是图片资源**：低多边形、平色块、硬边的贴图，
引擎按普通 PNG 加载（Ore 自带解码器），不做矢量多边形渲染。

    structure::
        wall::
            image:"art/wall.png"      # 相对**声明它的那个文件**；引擎加载时校验它存在
            solid:true

* 图片放 `art/`（或任何你喜欢的子目录），用相对路径引用（内容文件在 `content/` 里时写 `../art/wall.png`）；
* 文件不存在、或不是能解码的图片，加载报告里会有一条错误（不会静默画成空白）；
* **一块内容一张图**（不切片、不进大图集）、**尺寸随意**（一格通常 128 或 256 像素，引擎不缩放也不
  拒绝）、**命名不限**（官方内容用蛇形命名）——规则与理由见 `docs/MODS.md` §0。引擎只把整张图按格子
  铺上去，所以描边、渐变、半透明与动画帧都是你在图片里画的东西；这些**还没有约定**，连同配色表、
  一个结构跨格怎么办、每个瓦片层用哪些图，都等设计者给规则（`docs/GAME_DESIGN.md` §7 第 13 项）。

引擎侧的现状：包加载时解析并校验 `image`（存在、且是 PNG），画到屏幕上的是沙盒的试玩
（`docs/SANDBOX.md` §9）与世界视图——带图的内容按格子铺开，一格一张，屏幕上有几种图就是几个批次。

## 关于"没有玩家角色"

游戏没有角色，所有玩家都是上帝视角：输入驱动相机（平移/缩放）与指针（指向格子、框选、下达动作）。
所以包里**不会有**玩家贴图、角色数据或出生点这类条目——需要的是地图、结构、机器、配方与需求。
